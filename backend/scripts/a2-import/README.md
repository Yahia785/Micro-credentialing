# A2 pilot import (ECE 2514, Assignment 02)

Imports students' GitHub Classroom submissions for the interview pilot. Never put real student code, repositories or the roster in this repo (it is public); keep them outside it.

- `import.js` imports repositories (folders or clone URLs). `--dry-run` does everything except S3 and the table and writes the records as JSON to a folder outside the repo.
- `delete.js` deletes the S3 objects and the record of one username, a list of usernames, or everyone whose consent is not "yes". Dry run unless `--confirm`.
- Fake test repositories: `node scripts/eval/a2/make-test-repos.js` (writes to `D:/a2-pilot-test`, refuses a folder inside the repo).

What the import does for each repository: picks the last commit with a committer date before the deadline (dates come from git and a student can edit them), reads `functions.h` and `functions.cpp` with `git show` (nothing is checked out), builds with the student's header and then the official one, finds which of reverseList, splitString, playCraps and mode exist (the driver leaves out a missing one), runs every candidate input of `questions.json` under AddressSanitizer and UBSan in Docker (`gcc:13`, `--network none`), runs them again with the runner's flags, uploads the two files and writes the record. Needs Docker running; temporary copies of the student's files are deleted at the end.

Storage: the files go to the recordings bucket (`micro-credentialing-recordings`) under `a2-pilot/<importId>/` with server-side encryption AES256, the same as that bucket's default (SSE-S3). The path never contains the GitHub username. The record goes to `ImportedSubmissions-<env>` (key `importId`, index `GithubUsernameIndex` on `githubUsername`). No Lambda has access to the table yet.

Statuses: `ok`, `no_version_before_deadline`, `missing_files` (no functions.cpp at that commit), `file_does_not_compile` (the whole file does not compile; some interview functions compile alone) and `nothing_compiles` (no interview function compiles). When the whole file does not compile the import splits it into its top-level functions (matching braces), blanks every function but the one under test (so line numbers stay the student's) and compiles each interview function with the top part and the helpers it calls; if the error is outside the functions (a bad global, say) each function is tried again with only the top part's #include and using lines (a test build only; the stored code is never changed) and the error is recorded once as `outsideFunctionsError`; mode is needed only when an interview function has no definition at all; each function records `compilesAlone` and its first compiler error (line and message, no source). A username that is already in the table is skipped; delete it first.
