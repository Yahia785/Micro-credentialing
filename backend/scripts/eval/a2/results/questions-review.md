# A2 question review

Generated from `questions.json` and `results/harness.json` (the local run, GCC 14.2). No scripted student answers.

## Part 1. The questions as a student sees them

Each student gets one main question per function. The type rotates by form: **form A** = reverseList predict, splitString tracing, playCraps predict. **form B** = reverseList tracing, splitString predict, playCraps tracing. mode is the backup: it replaces a function that cannot be asked and takes that function's type. [INPUT], [K] and [LINE] (the student's own breakpoint line) are filled per student.

### reverseList

**Predict:** What would the vector hold after your reverseList runs on [INPUT]?

**Tracing:** You put a breakpoint on line [LINE] and run reverseList on [INPUT]. When it stops for the [K]th time, which two numbers are about to be swapped?

### splitString

**Predict:** What does your splitString return for [INPUT]?

**Tracing:** You put a breakpoint on line [LINE] and run splitString on [INPUT]. When it stops for the [K]th time, what piece is about to be added?

### playCraps

**Predict:** What does your playCraps return for [INPUT]?

**Tracing:** You put a breakpoint on line [LINE] and run playCraps on [INPUT]. When it stops for the [K]th time, what is the sum?

### mode (backup)

**Predict:** What does your mode return for [INPUT]?

**Tracing:** You put a breakpoint on line [LINE] and run mode on [INPUT]. When it stops for the [K]th time, what are the value and its count that are about to be checked?

### What-if follow-up (all functions)

If you changed line [LINE] of your code from `[FIND]` to `[REPLACE]`, what would your [FUNCTION] return for [INPUT]?

For reverseList: If you changed line [LINE] of your code from `[FIND]` to `[REPLACE]`, what would the vector hold after reverseList runs on [INPUT]?

Asked only after a correct main answer (engine rule comes in M4). The answer comes from running the student's changed copy. It is prepared for every function before the interview. The rules:

- The what-if output must differ from the student's plain output on the chosen input.
- If the student's plain output differs from the spec answer, the what-if output must not equal the spec answer (the change must never be the fix).
- If no line passes both checks, the what-if is skipped for that function and the reason is logged.

## Part 2. What each submission would be asked

Columns: the question with the input and K filled in; whether the input is targeted (and why, when it is not); the answer from that submission's own code (predict: what it returns or leaves in the vector; tracing: its own trace at the K-th stop, there is no spec answer); the spec answer (predict only); the prepared what-if follow-up with its answer, or why it is skipped.
